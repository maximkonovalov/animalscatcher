# Pinned for reproducibility: PytorchWildlife's classifier output schema
# has changed across releases (see the label/prediction/y_pred fallback
# in ac.py), so an unpinned upgrade can silently break species labeling.
# The full set below (numpy, setuptools included) was verified together
# as one `pip install -r requirements.txt`, from a clean venv, with no
# conflicting/overriding installs needed afterward.
#
# opencv-python-headless (not opencv-python): ac.py never uses any GUI
# feature (no imshow/waitKey), and the non-headless build pulls in
# libGL/GTK/X11 system libraries that a headless server or minimal
# Linux CI image won't have installed.
opencv-python-headless==4.10.0.84

# PytorchWildlife's detector/classifier constructor APIs differ between
# releases (the version string MegaDetectorV6 accepts, and whether
# DFNE/DeepfauneClassifier even exist) -- see ac.py's MegaDetectorV6 and
# DFNE calls, which are written against this exact version.
PytorchWildlife==1.3.0

# >=2.33 (not just >=2.32.3): older requests' check_compatibility() only
# accepts chardet <6.0.0, and chardet is an unpinned transitive dependency
# (via PytorchWildlife) that resolves to newer versions on some machines
# (seen: 7.6.0) -- outside that range it's a RequestsDependencyWarning on
# every import. 2.34.2 widens the accepted range to <8.0.0. This also
# requires Python>=3.10, which is fine: 3.10 is already this project's
# only verified/targeted interpreter (see README System Requirements).
requests==2.34.2

# numpy<2: torch==2.2.2 (pinned below) is compiled
# against the numpy 1.x ABI. A newer opencv-python/opencv-python-headless
# (>=5, pulled in transitively) requires numpy>=2, which silently breaks
# torch.from_numpy() at runtime (RuntimeError: Numpy is not available)
# if left unpinned -- pinning opencv-python-headless above avoids that
# newer opencv in the first place, but pin numpy explicitly too so the
# resolver can't drift here again.
numpy==1.26.4

# torch/torchvision/torchaudio are pinned together because
# PytorchWildlife declares all three unpinned, and torchaudio's compiled
# libtorchaudio.so only loads against the torch it was built for. Left
# floating, a Linux install resolved torch 2.12.1 next to torchaudio
# 2.11.1 (whose own metadata only asks for torch>=2.11), and `import
# PytorchWildlife` -- which imports torchaudio unconditionally, through
# its bioacoustics module -- failed with "undefined symbol:
# torch_exception_get_what_without_backtrace", so every test died at
# collection. 2.2.2 is also the last torch with Intel-Mac wheels, i.e.
# what this project is actually developed and deployed against;
# torchvision 0.17.2 and torchaudio 2.2.2 are its matching releases.
#
# Dependabot flags torch 2.2.2 (nine advisories, one Critical) and, each time
# one of them gains a fix, opens a security-update PR that bumps torch alone
# (2.13.0 on 2026-10-31: CI failed, the auto-close workflow closed it). That
# can't be merged, and no bump fixes it for this deployment: the newest
# torch, torchvision and torchaudio on PyPI with a macOS x86_64 wheel are
# exactly the pins below (newer releases ship macosx_14_0_arm64 only, and the
# latest torch needs Python >= 3.11), so a bump makes `pip install -r
# requirements.txt` fail on the Intel Mac mini this runs on. Checked each
# advisory individually rather than assuming:
#   - CVE-2025-3730, -3001, -2999, -3000, -2953, -2998 and -2149 are
#     local-only denial-of-service or memory-corruption bugs in single ops
#     (ctc_loss, lstm_cell, unpack_sequence, jit.script, mkldnn_max_pool2d,
#     pad_packed_sequence, the quantized Sigmoid) that need attacker-chosen
#     arguments to functions this daemon never calls: its only input is camera
#     frames, through MegaDetector's and the classifiers' inference.
#   - CVE-2025-2148 (network vector, Low) is in torch.ops.profiler internals,
#     which nothing here touches.
#   - CVE-2025-32434 (Critical): torch.load(weights_only=True) can still run
#     code from a malicious checkpoint. ac.py never calls torch.load, but the
#     libraries it uses do, on the model weights they download on first run
#     (MegaDetector's from Zenodo, SpeciesNet's from Kaggle, DFNE's from wherever
#     PytorchWildlife fetches them), so the way in is a compromised download
#     source or a broken TLS connection to one. A bump isn't available as a
#     mitigation (above), so the weights are what to protect: don't point
#     speciesnet_model at a file of unknown origin.
torch==2.2.2
torchvision==0.17.2
torchaudio==2.2.2

# setuptools==59.5.0: yolov5 (a transitive dependency via PytorchWildlife)
# imports pkg_resources at module level. Modern setuptools (~80+) removes
# pkg_resources entirely; this older setuptools still has it. (On Python
# 3.12, this same setuptools version instead breaks a different way --
# see README System Requirements for why this project targets Python
# 3.10.)
#
# Dependabot will keep flagging this version for CVE-2025-47273,
# CVE-2024-6345, and CVE-2022-40897 (all High) plus CVE-2026-59890
# (Moderate), and since 2026-10-23 for GHSA-xmj3-9gf7-h52w (Low) -- checked
# each advisory individually rather than assuming:
# the first four require actually invoking setuptools' deprecated
# PackageIndex/easy_install download machinery against an untrusted
# package index (the first three), or building this project's own sdist
# to publish it (the fourth); the fifth needs a crafted wheel fed to
# setuptools' legacy Wheel.install_as_egg on Windows, and this runs on
# macOS and Linux. Nothing here does any of it -- this pin only
# exists for yolov5's passive `import pkg_resources`, and deploy.sh's
# `pip install -r requirements.txt` goes through pip's own modern
# installer, never setuptools' legacy download path. Bumping past
# ~80 to silence these would break the pkg_resources import above for a
# security benefit that doesn't apply to how this project actually uses
# setuptools -- don't bump this without re-solving that conflict first.
setuptools==59.5.0

# PytorchWildlife's own package metadata doesn't declare these, but its
# top-level __init__.py unconditionally imports a bioacoustics submodule
# that needs them -- so `import PytorchWildlife` fails without them even
# though ac.py never uses audio features. llvmlite/numba are pinned to
# versions with working prebuilt wheels (an unpinned/latest llvmlite
# fails to build from source on at least one verified platform).
soundfile==0.14.0
librosa==0.11.0
numba==0.68.1
llvmlite==0.43.0
